接入指南

        

          
1. 生产接入步骤

          
    
            
  1. 在“设置”中选择 jt400 适配器，填写 IBM i 服务器地址、服务账号、密码和要监控的 subsystem。
    2. 
            
  2. 点击“测试连接”确认可达；服务账号需具备读取 job 列表、读取消息队列、发送 reply 的权限（通常需要 *JOBCTL 及对应消息队列权限）。
    3. 
            
  3. 默认关闭 Dry-run，守卫会自动扫描并按规则回复。如需先只读验证，可临时开启 Dry-run，用“规则测试台”和“模拟注入”观察命中结果。
    4. 
            
  4. 验证完成后务必关闭 Dry-run（概览页也有快捷按钮），否则回复不会真正发出，job 会一直停留。
    5. 
          

          
2. 已核对的 JTOpen API（jt400 11.2）

          
    
            
  • JobList.addJobSelectionCriteria(SELECTION_ACTIVE_JOB_STATUS, Job.ACTIVE_JOB_STATUS_WAIT_MESSAGE) 发现 MSGW job
    • 
            
  • Job.getSubsystem() 按 subsystem 过滤
    • 
            
  • MessageQueue.getMessages(...) 读取待回答消息，reply(messageKey, text, true) 回复
    • 
            
  • Job.end(0) 按规则结束 job（等价于 ENDJOB *IMMED）
    • 
          

          
3. 消息队列路径

          
默认模板为 /QSYS.LIB/{job}.MSGQ。如果现场 job 的消息队列不在此位置，请在“设置”中调整模板，可用占位符 {job}、{user}、{number}。

          
4. 排查“扫描不到 job”

          
    
            
  1. 设置页先选对适配器 jt400，填完服务器/用户/密码/subsystem 后必须点“保存设置”；仅点“测试连接”不会保存。
    2. 
            
  2. 用“诊断扫描”查看：连接是否成功、活动 job 总数、各状态分布、MSGW job 数量、subsystem 过滤后剩下的 job。
    3. 
            
  3. 如果活动 job 总数为 0，说明该账号看不到 job 或筛选条件不对；如果 MSGW 数量为 0，说明当前确实没有处于消息等待状态的 job。
    4. 
            
  4. 如果 MSGW 有值但过滤后为 0，检查 subsystem 是否填对（支持 * 通配，例如 QUSR*）。
    5. 
            
  5. 日志在 data/guard.log，控制台也会同步输出扫描、命中和回复记录。
    6. 
          

          
5. 启动

          
本程序是普通可执行 jar：java -jar msgw-guard-1.0.0.jar，默认监听 http://localhost:8088。配置和规则保存在 jar 同目录下的 data/ 文件夹。

          
6. cancel 后行为

          
按规则回复 CANCEL 后，守卫会停止处理该 job 并在“概览”页产生醒目提醒，不会自动续跑后续调度。人工确认后可在“已停止的 job”中恢复。
